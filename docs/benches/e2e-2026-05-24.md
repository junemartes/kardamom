# Cross-component sustained-load benchmarks — 2026-05-24

**Status:** scaffold pending first real run.

The bench lives at `crates/kardamom-e2e/benches/e2e_throughput.rs` and is
gated behind `feature = "full-pipeline-e2e"`. It depends on Docker + cmake +
libuuid for the rusteron build; no machine in the current development
environment provides all three at once, so the table below is a placeholder
populated by the first CI run that opts into the `docker-e2e` workflow.

To run locally (once those deps are available):

```bash
cargo bench -p kardamom-e2e --features full-pipeline-e2e --bench e2e_throughput
```

## Methodology

- Single-node Aeron container (Media Driver + Archive).
- IPC channels for B and C (lowest-latency transport; matches the
  in-cluster topology spec §5).
- `criterion` for throughput at `batch={1, 64, 1024}` and round-trip latency
  for a single-message publish.
- Hardware: see `/proc/cpuinfo` table once the run lands.

- `kardamom-sealer/benches/boundary_emit.rs` (250 ms boundary cadence)
- `kardamom-batcher/benches/pack_throughput.rs` (blob pack rate)

If the end-to-end number is significantly below `min(per-tier numbers)`, the
gap is bridge overhead (the AeronRuntime command channel hop). Closing that
gap is a v0.2 optimisation: replace the `crossbeam::unbounded` command queue
with a lock-free SPSC ring per publisher handle, or push the publish encoding
onto the caller thread and submit only the AlignedVec to the Aeron thread.
