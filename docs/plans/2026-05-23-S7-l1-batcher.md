# S7 L1 Batcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `crates/kardamom-batcher` — an offline, archive-driven L1 batcher that reads `TxEnvelope` and `BlockBoundaryStart` records from channel B's Aeron Archive segment files (or the Aeron Archive replay protocol), packs them into EIP-4844 blobs (KAR1 + zstd framing, no state root per D-Sh11), and posts them to a pure data-availability sink contract `KardamomL2Settlement` deployed via the existing ERC-7955 factory.

**Architecture (per S0 D-Sh10 and D-Sh11):**
- **No live coordination with the sequencer.** The batcher consumes the on-disk archive only — it never subscribes to channel C, never queries a live sequencer process. It can be down for hours and catch up by replaying segment files when it returns.
- **Singleton + hot standby** via `kardamom-leases` (same lease primitive used by S2 and S5). The lease-holder runs the batching loop; standbys observe watermarks and take over deterministically when the leader drops.
- **Block-aligned batching.** Read txs from B sequentially; on each `BlockBoundaryStart`, close the current per-block batch and start the next one. Group N blocks per blob batch (config-driven; one block per batch is the simple default).
- **EIP-4844 blob packing.** Compress the KAR1 payload with zstd, slice into 31-byte-per-field-element chunks (BLS12-381 safe encoding via `alloy_eips::eip4844`), pad to `BYTES_PER_BLOB` (131,072), submit ≤6 blobs per L1 tx.
- **DA sink contract.** `KardamomL2Settlement.sol` records `(prevBatchIndex, blobVersionedHashes[], l2BlockStart, l2BlockEnd)` and emits `BatchPosted`. No state-root storage. Replay protection: contract stores `lastBatchIndex` and CAS-compares against `prevBatchIndex` on every post.
- **Reconstruction support.** Library function in `kardamom-batcher` rebuilds the L2 tx stream + block-boundary markers from `(L1 calldata, blob_bytes)` — used by the §6 conformance test in the parent system.

**Tech Stack:** Rust 2024, `alloy-eips` (4844 constants + `Blob` type), `alloy-consensus` (BlobTransactionSidecar), `alloy-provider` (broadcast), `zstd` (payload compression), `kardamom-types` (`TxEnvelope`, `BlockBoundaryStart`, `BPosition`), `kardamom-leases` (singleton election), `kardamom-log` (segment-file path + Aeron Archive client gated behind `aeron-live`), `kardamom-deployer` (extended with new `ContractId::KardamomL2Settlement` variant).

## KAR1 framing (no state root per D-Sh11)

```
+----+----+----+----+
| 'K'| 'A'| 'R'| '1'|     4-byte magic
+----+----+----+----+
| version (u8)      |     framing version, currently 1
+-------------------+
| flags    (u8)     |     bit 0 = zstd-compressed
+-------------------+
| block_count (u32) |     LE
+-------------------+
| reserved   (u16)  |     zero
+-------------------+
| for each block:
|   block_number     u64 LE
|   l2_timestamp     u64 LE
|   tx_count         u32 LE
|   for each tx:
|     correlation_id u64 LE
|     sender         20 bytes
|     tx_hash        32 bytes
|     raw_tx_len     u32 LE
|     raw_tx         raw_tx_len bytes
```

Explicitly **no `state_root` field** (D-Sh11). All multi-byte ints little-endian. After framing, the entire payload is zstd-compressed (flag bit 0 set), then sliced into 31-byte field-element chunks for blob packing.

## L1 settlement contract (`KardamomL2Settlement.sol`)

Pure DA sink. State:
- `address public l1Batcher` — only this address may call `postBatch`.
- `uint64 public lastBatchIndex` — monotonically increasing, set on every successful post.

External:
- `postBatch(uint64 prevBatchIndex, bytes32[] calldata blobVersionedHashes, uint64 l2BlockStart, uint64 l2BlockEnd)` — reverts unless `prevBatchIndex == lastBatchIndex && msg.sender == l1Batcher && blobVersionedHashes.length >= 1 && l2BlockEnd >= l2BlockStart`. On success: `lastBatchIndex = prevBatchIndex + 1`, emits `BatchPosted(uint64 batchIndex, bytes32[] blobHashes, uint64 l2BlockStart, uint64 l2BlockEnd)`.

No state-root field. No blob payload stored on chain — the EL provides the blobs separately via the 4844 sidecar, and `BLOBHASH` opcode would verify them if a future validator wanted to, but v0 only records the versioned hashes.

**Files:** `src/blob.rs`, `tests/blob_packing.rs`.

- [ ] **Step 1 (TDD):** Test cases:

  - `pack_to_blobs(&[0u8; 30])` returns 1 blob, first 31 bytes are `[0, 30u8 prefix??]` — actually use canonical EL-4844 encoding: pad input to a multiple of 31 bytes, then for each 31-byte chunk write a 32-byte field element where the high byte is 0 and the low 31 bytes are the chunk. ## Task 6: Offline archive segment reader (filesystem path)

**Files:** `src/archive_reader.rs`, `tests/archive_reader.rs`.

## Open questions / future work

1. **Real-Aeron replay protocol vs filesystem path.** v0 uses the filesystem path. Replay protocol via `rusteron_archive` is a future improvement when the batcher runs on a host without direct read access to `archive_dir`.
2. **Replacement-by-fee.** Not in v0 (S0 D-Sh9): if L1 stalls, the hot standby takes over and reposts. Acceptable for v0.
3. **Posted-batch reconciliation.** A future task could add a reconciler that periodically re-reads the contract's `lastBatchIndex` and the archive's tail position to surface lag.
4. **Validator subsystem.** Out of scope (D-Sh9, D-Sh11) — independent validators consume the archive + L1 posts and post their own state-root attestations.

## Cross-component readiness for a full pipeline e2e

For a true end-to-end "proxy → sequencer → channel B → executor → channel C → state writer; batcher reads B archive → posts to L1" Docker test:

1. **S1 ingress proxy** running and accepting JSON-RPC.
2. **S2 sequencer** subscribing to S1's published txs and publishing to channel B.
3. **S3 recorder** active and writing segment files; fsync sidecar emitting watermarks.
4. **S5 sealer** electing leader and publishing `BlockBoundaryStart` markers onto B.
5. **S4 executor** consuming B + emitting `BlockDelta`s + `Receipt`s + closing `BlockBoundary`s on C.
6. **S6 state writer** consuming C and updating libmdbx.
7. **S7 batcher** reading the archive segment files and posting to an anvil-backed L1.

S7's part of this story is independent (D-Sh10) — it only needs steps 1–4 to produce a useful archive, and can be tested standalone via Task 24/25 with synthetic archive contents.
