# validator

## Summary

The largest shape in this group is the test fixture. One signed-legacy-transaction
builder is written five times in the crate, a funded `MockStateDatabase` builder is
written eleven times in `engine_tests.rs`, and the whole channel-backed engine
harness in `forged_envelope_chaos.rs` is a copy of the executor's. The engine
already owns a private `test_support` module; making it public behind a feature is
the single highest-leverage change. In production code the biggest shapes are the
two parallel block drivers in `parallel/engine.rs`, the two feed-subscription loops
in `interop/serve.rs`, the divergence-latch guard repeated at three observer seams,
and the per-block accumulate-then-flush receipt sinks in `attester.rs` and
`interop/sink.rs`. Estimated reduction: about 270 lines of production code and about
490 lines of test code in this group, plus about 250 more lines in executor and
exec-core test files that the same shared harness would remove. Of the prior audit's
cross-cutting items, the binary-boilerplate items are mostly closed
(`obs::bin`, `AeronRuntime::spawn`, `connect_cluster_ordering`, `open_tx_receipts`,
`replay_unavailable_fallback`), the validator's triplicated tx/deposit dispatch is
closed, and three items stay open: `resume_point`, `restore_checkpoint_if_fresh`,
and the `env:VAR` key parser.
