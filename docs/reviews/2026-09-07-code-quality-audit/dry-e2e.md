# e2e

## Summary

The e2e crate holds 9,743 lines. Four shapes carry most of the duplication. First,
the scenario drivers repeat three loops: poll a validator metric past a threshold,
poll the executor block number, and nudge the chain with transfers until state
settles. Second, the interop scenarios (`xchain.rs`, `xchain_two_stacks.rs`,
`xchain_da_parity.rs`) repeat the 0x7D delivery-receipt assertions and the lane
cursor check. Third, `harness/services.rs` and `harness/l2.rs` repeat per-service
argument blocks and per-transaction-kind signing bodies. Fourth, the test files
repeat the tuned-park stack launch and the interop rig. Estimated reduction inside
`crates/e2e`: about 500 lines (390 production, 116 tests). One cross-crate helper
adds about 110 more lines: the anvil bridge bootstrap exists three times
(`e2e`, `validator` tests, `deployer` tests). Prior-audit items: `validator_root`
and the `super::bridge::` reach-through are DONE. The anvil-skip and
`stack.target(...)` item is PARTLY done. The submit-batch and poll-metric-until
item is still OPEN.
