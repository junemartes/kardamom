# 17 88931ed — fix(ci): repair cluster-e2e load smoke (errexit + nonce collision)

## Summary of change
Fixes two test-harness bugs that failed the cluster-e2e load smoke on healthy runs. (1) The receipt-latency percentile `awk` printed `p50 p99 max` with no trailing newline into `read -r ... < <(...)`; `read` returns 1 on EOF-without-delimiter, which under `set -euo pipefail` killed smoke-load.sh right after a successful receipt drain — the missing `\n` is added. (2) smoke.sh (gate + churn re-smoke) and smoke-load.sh both signed from Anvil account #0, colliding on nonces; a new `SMOKE_SENDER_OFFSET` knob shifts the load smoke's sender window within the 16-key table, and ci-cluster.sh runs it with offset 1 so account #0 stays reserved for the single-tx smokes.

## Findings

### F17.1 [nit] [quality] — Out-of-range SMOKE_SENDER_OFFSET is clamped silently, and a negative value clamps back onto the reserved account
- **Where**: deploy/cluster/scripts/smoke-load.sh:149-152 (at the commit); deploy/cluster/scripts/smoke-load.sh:154-155 at HEAD
- **What**: `SMOKE_SENDER_OFFSET < 0` is silently clamped to 0 — i.e. exactly the reserved account #0 the knob exists to avoid — and `> 15` is silently clamped to 15 (forcing SMOKE_SENDERS to 1). A caller typo would silently reintroduce the nonce collision (or degrade the load to one sender) with no diagnostic. Consistent with the pre-existing silent SMOKE_SENDERS clamp, so cosmetic.
- **Still present at HEAD**: yes
- **Suggested fix**: Emit a `warn` line when either clamp fires (or hard-fail on a negative offset).

## Verdict
Correct and well-reasoned. Both diagnoses check out: `read -r a b c < <(printf "%s %s %s")` does exit 1 without a trailing newline (errexit then kills the script only on healthy runs — a nasty inversion), and the added `\n` fixes it; the offset mechanism correctly maps logical sender `s` to key index `offset+s` while keeping per-sender nonce tracking on `s`, and the clamp keeps the `offset+count` window inside the 16-key table. The `NONCE=1` churn re-smoke coordination this commit documents was later superseded at HEAD by the per-check dedicated-account scheme (smoke.sh is now always nonce 0 with a PK knob), but `SMOKE_SENDER_OFFSET=1` itself survives and is still used by ci-cluster.sh (line 532 at HEAD). Only a cosmetic finding.
