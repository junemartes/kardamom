# 20 33137df — fix(ci): rustfmt + clippy (rust 1.96 lints) + bench boundary alignment

## Summary of change
Unbreaks CI after the toolchain moved to Rust 1.96: a workspace-wide `cargo fmt` (import reordering + reflow across 13 files), fixes for new clippy lints (`explicit_auto_deref`, `manual_is_multiple_of`, `question_mark`, `field_reassign_with_default`, `len_without_is_empty`, `empty_line_after_doc_comments`), and one real test fix — the executor `sequential_throughput` bench passed `BlockBoundaryStart.end_tx_idx` as the last tx *index* (`BATCH-1`) instead of the cumulative record *count* (`BATCH`), tripping the executor's `BoundaryMisaligned` check.

## Findings
None. Behavior-equivalence was checked change-by-change:

- **Bench boundary alignment** (crates/executor/benches/sequential_throughput.rs:222-230): the executor's check (actor.rs:418-430 at the commit) compares `end_tx_idx.as_index()` against `expected_tx_idx` — the count of applied canonical records, which after BATCH TxRefs is BATCH, not BATCH-1. The old `pos(BATCH-1)` (= `from_index(BATCH-1)`, since `pos(off)` is `{term_id:0, term_offset:off}` and `from_index` puts the low 32 bits in `term_offset`) was genuinely wrong per the documented `BPosition::from_index` contract (position.rs:35-47) and matches the in-crate unit test (actor.rs:634-638: 2 records → `pos(2)`). This is a test-side fix aligning the bench to canonical semantics; no production code path changes.
- **executor question_mark refactor** (actor.rs:199-219): `let pipeline = r_b.and(r_exec).and(r_commit); if pipeline.is_err() { return pipeline; } ... pipeline.and(r_a).and(r_dep)` became `r_b.and(r_exec).and(r_commit)?; ... r_a.and(r_dep)`. Identical: on Err it returns the same first error (`?` on the same error type is an identity conversion); on Ok, `Ok.and(x)` ≡ `x`. The early-return-before-joining-A-readers ordering (which prevents the documented hang) is preserved.
- **`x % n == 0` → `x.is_multiple_of(n)`** (actor.rs:534, offer_retry.rs:84): identical for the unsigned operands used, including 0.
- **`&**aeron` → `aeron`** (aeron_live.rs:622): auto-deref, same value.
- **`field_reassign_with_default` → struct literals** (config.rs tests): same field values via `..Default::default()`.
- **seen_receipts.rs:72 `pub fn len` → `fn len`**: the method is `#[cfg(test)]`-only; visibility narrowing is safe.
- **offer_starvation.rs:148-153 let-chain collapse**: `if let Ok(Some(..)) = timeout(...) { if e.correlation_id == 2 { ... } }` → `if let ... && e.correlation_id == 2` — same control flow.
- Everything else is pure rustfmt reflow (verified no token-level changes beyond formatting in aeron_live.rs, publisher.rs, config.rs, the three log tests, the sealer/sequencer/ingress bins, multiprocess_e2e.rs doc-comment blank line, and the position.rs test array reflow).

## Verdict
Clean. Despite the wide diff, the only semantic change is the bench's `end_tx_idx`, and that is a correct fix of the bench (test data) to the documented count-based contract — the executor's `BoundaryMisaligned` check itself is untouched. All clippy-driven rewrites are behavior-preserving.
