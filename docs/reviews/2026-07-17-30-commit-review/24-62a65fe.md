# 24 62a65fe — refactor(state): remove dead/legacy code and tech debt (#47)

Dead-code cleanup of `kardamom-state`: removes the never-called `swap_compacted` half of the compaction API, the `StateEnvBuilder::max_readers` setter, write-only-table decoders `decode_block_key`/`decode_header_value` (plus their roundtrip tests), capacity-planning consts `BYTES_PER_BLOCK`/`HORIZON_BYTES` (plus the tautological `horizon_math_holds` test), the dead `DurableCursors` cluster and `RecoveryPoint::genesis`, two never-constructed error variants (`WriterChannelClosed`, `SnapshotExhausted`), the unused `bench-internals` feature, and unused `anyhow`/`metrics` dependencies.

## Findings

Dead-code verification: grep at the commit tree and at HEAD found zero references to any removed item (`swap_compacted`, `max_readers` setter, `decode_block_key`, `decode_header_value`, `BYTES_PER_BLOCK`, `HORIZON_BYTES`, `RecoveryPoint::genesis`, `DurableCursors`, `WriterChannelClosed`, `SnapshotExhausted`, `bench-internals`). The `max_readers` struct field and its `MAX_READERS` default remain intact at HEAD (crates/state/src/env.rs:46,54,79) — only the unused override setter went. No `metrics::`/`anyhow` usage exists in the crate, so the dependency removals are correct. The three deleted tests exercised only deleted code, so no live-path test coverage was lost.

### F24.1 [nit] [quality] — Encoders for on-disk formats now have no roundtrip verification
- **Where**: crates/state/src/schema.rs (encode_block_key:~115, encode_header_value:~131 at HEAD)
- **What**: `block_key_roundtrip` and `header_value_roundtrip_no_state_root` were the only tests pinning the byte layout of `encode_block_key` and the 20-byte `encode_header_value`, both still written to disk by the writer (crates/state/src/writer.rs:264). Removing the decoders (genuinely dead) took the encoder coverage with them. If the layout of a persisted format drifts, no test catches it. This is a marginal loss — the encoders are simple `to_be_bytes` concatenations — but they define an at-rest schema.
- **Still present at HEAD**: yes
- **Suggested fix**: Add a small test asserting the expected byte layout of `encode_header_value`/`encode_block_key` against literal byte arrays (no decoder needed).

## Verdict
Clean and accurate removal-only commit; every deleted item was verifiably unreferenced at the commit and at HEAD, error variants were genuinely never constructed, and dependency/feature pruning matches usage. The only (minor) functional regression is the loss of roundtrip coverage for two still-live on-disk encoders, which is easy to restore with layout-literal tests.
