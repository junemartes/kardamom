# 21 d76c4f8 — test(e2e): fail instead of skip when docker/anvil unavailable

## Summary of change
Converts four soft-skip guards in the e2e crate's docker-gated tests (full_pipeline_e2e.rs and the three multiprocess_e2e.rs tests) from `eprintln!("skipping: ..."); return;` — which counts as a green pass — into hard `assert!`/`expect` failures when Docker or anvil is unavailable. Rationale: these tests only run when explicitly opted in (`--features full-pipeline-e2e -- --ignored`), an environment where Docker/anvil are required, so their absence is an error, not a skip condition.

## Verdict
Correct and safe change. The risk of breaking developer machines is nil because every converted test is doubly gated — `#![cfg(feature = "full-pipeline-e2e")]` plus `#[ignore]` — so it only runs when deliberately invoked, exactly the context where a missing dependency should fail loudly. The one weakness is incompleteness: the identical pattern survives in the kardamom-log docker tests (F21.1), one of which CI actually executes. Note the four converted call sites themselves no longer exist at HEAD — crates/e2e/tests/ was deleted wholesale in 471d39d (cluster-only migration) — so the commit's direct effect was short-lived, but F21.1 remains actionable.
