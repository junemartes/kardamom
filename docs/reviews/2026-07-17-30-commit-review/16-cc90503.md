# 16 cc90503 — Merge pull request #42 (claude/cluster-mds)

## Summary of change
Large merge (~4.7k insertions, 123 files) that reworks the cluster transport and durability model: tx_ordering moves to Aeron MDC with the sealer as the sole canonical publisher (republish + dedup + count-based `end_tx_idx` boundary alignment via `BPosition::from_index`), tx_receipts moves to per-replica MDS fan-in with tx-hash dedup at ingress (`SeenReceipts`), and the N-recorder Q-of-N quorum (crate `kardamom-recorder`, `watermark::QuorumState`, quorum/recorder Nomad jobs) is replaced by an archive-at-the-sealer durability sidecar. The Aeron thread's blocking `offer_blocking` is replaced by a pending-publish retry queue (`drain_pending`) so a back-pressured publish can no longer starve subscription polling (the root cause of the cluster tx_ordering freeze), plus a deadline-based `offer_with_deadline` for the connect race. The deploy stack is rebuilt around a node-class model (11 containers, generated inventory, new IPs, load-smoke script, local Docker-Desktop harness), and large amounts of dead code are removed across ~14 crates.

## Findings

### F16.1 [medium] [logic] — Static-inventory (Vagrant/`make provision`) path broken: templates require `tier`/`node_ip` the inventories don't define, and their roles/IPs contradict the new contract
- **Where**: `deploy/cluster/ansible/roles/nomad/templates/nomad.hcl.j2:39,42`, `roles/consul/templates/consul.hcl.j2:4` (at commit and at HEAD) vs `deploy/cluster/ansible/inventory.ini` and `inventory.containers.ini` (no `tier=`/`node_ip=` host vars, at commit and HEAD); consumed by `deploy/cluster/Makefile:33` (`ansible-playbook -i ansible/inventory.ini`)
- **What**: The commit switched `nomad.hcl.j2`/`consul.hcl.j2` from `cluster_nodes[kardamom_node].ip` to `{{ node_ip }}` and added `{{ tier }}`, which only the inventory *generated by ci-cluster.sh* provides. The hand-written `inventory.ini`/`inventory.containers.ini` were updated to an 11-node layout but define neither var, so `make provision` fails on undefined Jinja variables. Even if provisioned, those inventories give `role=worker` to exec1/ingress1/sealer1/aux nodes while the new Nomad jobs constrain on `role==executor/ingress/sealer/aux` (nothing would place), and their IPs (exec1=.31, sealer1=.33) contradict `group_vars`/`channels.toml.tpl` (executor=.41, sealer canonical MDC publisher=.51, receipts host=.31=ingress) — the MDC/MDS endpoint contract would be wrong on that topology. Only the ci-cluster.sh generated path is coherent.
- **Still present at HEAD**: yes (inventories still lack `tier`/`node_ip`; Makefile still wires inventory.ini; inventory.containers.ini is now dead — ci-cluster.sh generates its own)
- **Suggested fix**: Either delete the static inventories + Vagrant path or regenerate them from `node_classes` (same generator as ci-cluster.sh), and give the templates `| default(...)` fallbacks so a missing var fails with a clear message.

### F16.4 [low] [logic] — smoke-load.sh direct-scrape IP map still uses the removed r1..w2 topology

### F16.5 [low] [logic] — Pending-publish queue: caller ack-timeout does not cancel the queued frame; deadlines behind a blocked head are enforced only serially
- **Where**: `crates/log/src/aeron_live.rs` — `PubHandle::publish_bytes` (10 s `recv_timeout`, HEAD ~line 820) vs `drain_pending_inner` (HEAD ~lines 707-765): a `blocked` pub's non-head entries are `keep`ed without an offer attempt, so their `deadline` is never evaluated until they reach the head
- **What**: With a never-connecting subscriber, queued frames on one publication expire one-by-one (~`OFFER_TIMEOUT` = 5 s each). A caller whose frame is ≥2 deep can hit the 10 s ack timeout and report failure while its frame is still in `pending`; if the subscriber then connects, the frame is delivered *after* the caller treated the publish as failed. A caller that retries on error (the pattern this PR introduces for must-deliver streams) then publishes the payload twice; receipts are deduped at ingress, but other ack'd streams using `publish_bytes` have no dedup.
- **Still present at HEAD**: yes
- **Suggested fix**: Check `deadline` for every retained entry each pass (not only on an offer attempt), and/or drop the entry when its ack receiver is disconnected (caller gave up), so a timed-out publish can never be delivered late.

### F16.7 [nit] [quality] — `open_subscription_with_id` duplicates `open_subscription_merged`'s decode/deliver closure

### F16.8 [medium] [quality] — Aeron thread busy-spins whenever any sub/pending exists; comment claims a "short sleep" that did not exist
- **Where**: `crates/log/src/aeron_live.rs` `run_aeron_thread` step 4 at the commit (only `subs.is_empty() && pending.is_empty()` blocked; the else path had no sleep despite the comment "a short sleep keeps the poll/retry cadence tight without busy-spinning a core")
- **What**: In every deployed service (subs are always non-empty) the loop spun at 100% CPU; with the new per-executor second runtime (`rt_pub`) that was two pinned cores per executor, in a cluster already tuned for CPU thrift (SHARED driver threading, 2 s sealer tick). The doc comment described behaviour that wasn't implemented.
- **Still present at HEAD**: no (fixed by 471d39d, which added `else { std::thread::sleep(Duration::from_micros(100)) }`)
- **Suggested fix**: n/a (fixed).

### F16.9 [medium] [logic] — Commit-thread must-deliver retry loops forever on permanent errors, recreating the "frozen but alive" mode
- **Where**: `crates/executor/src/actor.rs` `spawn_commit` at the commit (`while let Err(e) = c_pub.publish(c_msg.clone()) { … sleep 50ms }`)
- **What**: The infinite retry treats every error as transient. On a permanent failure (Aeron runtime dead → `TxReceiptsClosed`, publication closed) the commit thread spins forever emitting a warn every 20 attempts, the process stays "running", and the orchestrator never restarts it — exactly the frozen-but-alive failure the same commit's join-order fix is written to avoid. No cap, no permanent/transient error distinction, no shutdown check.
- **Still present at HEAD**: no (actor.rs removed in 0e079c9, PR #63 validator rework)
- **Suggested fix**: n/a at HEAD; pattern to avoid if reintroduced — classify `PUBLICATION_CLOSED`/runtime-dropped as fatal and exit the process.

### F16.10 [medium] [logic] — IPC-fallback `end_tx_idx` count comes from an asynchronously lagging tail-tracker → spurious fatal BoundaryMisaligned under load
- **Where**: `crates/sealer/src/bin/kardamom-sealer.rs` at the commit (single-host `else` branch: passive `tail_sub` task bumps `canonical_count`; `TxOrderingBoundaryAdapter::publish` stamps the boundary from that count)
- **What**: In the shared-channel path the sequencers publish TxRefs directly; the sealer's counter only advances when its own subscription *delivers* each record, which lags the stream. A boundary offered while a just-published TxRef is still in flight to the tail-tracker is stamped with count N while the executor (which counts in stream order) has applied N+1 by the boundary — and the executor now treats a count mismatch as fatal (`BoundaryMisaligned` → process exit/crash-loop). The MDC path is correctly serialized under `publish_lock`; the IPC path has no such serialization and cannot have one (it doesn't own the sequencer publishes).
- **Still present at HEAD**: no (the sealer binary was removed in 471d39d, PR #67 — Raft/Aeron-Cluster sealer)
- **Suggested fix**: n/a at HEAD.

## Verdict
This is a substantial, mostly well-executed re-architecture with unusually good failure-analysis commentary: the pending-publish retry queue genuinely fixes the publish-starves-subscription freeze (and is pinned by both unit tests and a real-Aeron regression test), the count-based `end_tx_idx` is a sound replacement for fragile Aeron byte positions, and the MDS fan-in dedup is layered over already-idempotent sinks. The Rust-side risks that shipped with it (infinite must-deliver retry, the IPC boundary-count race, the busy-spinning Aeron thread) were all superseded or fixed by later commits. What remains actionable at HEAD is deploy-tooling drift the commit itself created: the static-inventory/Vagrant path is inconsistent with the new template variables and role/IP contract (F16.1), and several stale references (justfile doctor check, workflow diagnostics container names, smoke-load IP map, vestigial recorder config) will bite the next person to touch the cluster harness. The library-level pending-queue cancellation gap (F16.5) is worth a small hardening pass since retry-on-publish-error is now the house pattern.
